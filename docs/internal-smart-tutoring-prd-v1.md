# 内部智能化托辅班学管系统 PRD（V1.0）

## 文档信息
- 版本：V1.0
- 日期：2026 年 7 月
- 状态：草稿
- 适用范围：暑期托辅班内部使用（支持后续 SaaS 化）

## 1. 项目概述
### 1.1 项目背景
暑期托辅班教师普遍面临作业批改量大、学情分析耗时、学生行为记录碎片化等问题。系统目标是提供免安装、移动优先的智能化学管能力，显著降低教师重复劳动。

### 1.2 产品目标
- 核心目标：教师每日“作业批改 + 学情记录”耗时减少 **60%+**。
- 业务目标：提升教学质量与家长满意度，支持续班率提升。
- 技术目标：构建稳定、可扩展的 AI+业务融合架构，优先使用国产大模型。

### 1.3 用户画像
- 校长 / 教务：查看全校与年级数据、绩效分析。
- 年级主任：管理本年级班级与整体学情。
- 班主任 / 任课老师：作业批改、学生建档、基础学情查看（核心用户）。

### 1.4 成功指标（KPI）
- 教师批改作业耗时减少 ≥60%
- 系统日活跃教师率 ≥90%
- AI 批改准确率 ≥92%（可人工修正）
- 平均每班每周使用系统 ≥5 次

## 2. 权限与组织架构（RBAC + 多租户）
### 2.1 角色与数据可见范围
- 校长（Super Admin）：全校数据
- 年级主任（Grade Leader）：所属年级数据
- 老师（Teacher）：所属班级数据

### 2.2 分层结构
Student → Teacher → Grade Leader → Dept Head → Principal（Super Admin）

### 2.3 数据模型约束
- 所有核心业务表增加 `school_id`（或 `campus_id`）以支持多租户与后续 SaaS 化。
- 所有数据读写接口必须执行基于角色与组织关系的可见性校验。

## 3. 核心功能模块（V1.0 精简版）
### 模块一：基础数据与组织管理
- 组织树：年级 → 班级（支持动态增删改）
- 人员管理：教师增删改查 + 角色/班级分配
- 学生管理：单个创建 + Excel 批量导入（姓名、性别、年龄、家长电话、头像）

### 模块二：AI 拍照批改与学情分析（核心）
流程：教师手机拍照上传 → AI 异步识别 → 结构化结果入库 → 展示

能力要求（V1.0）：
- 国产 VLM 优先：千问 VL（Qwen-VL）、Doubao Seed Vision 等
- 对接知识点字典（标准知识点）
- 输出强制 JSON（见接口规范）
- 错题统计：
  - 纵向：题目错误率 + 高频知识点
  - 横向：学生个人知识点掌握情况（雷达图/列表）

### 模块三：学生数字化建档
- 学生主页：Timeline 展示日常记录、作业表现、照片
- AI 行为分析：输入碎片化文字/语音转文字，抽取正负向标签并生成结构化摘要

### 模块四：基础看板与数据呈现
- 班级学情概览页（错题 Top 知识点、学生掌握情况）
- 个人学生主页

### V2.0 预留能力（架构需兼容）
- 个性化“举一反三”变式题 + PDF 导出
- AI 家校沟通助理
- 自动周/月学情报告
- 作业布置与统一试卷管理

## 4. 非功能性需求
- 性能：支持至少 200 名教师并发
- 可用性：Mobile-First，PWA 支持离线上传队列
- 稳定性：所有 AI 调用异步化，避免接口超时
- 安全性：隐私数据加密、访问日志、照片脱敏，符合个人信息保护要求
- 可扩展性：多租户与模块化设计

## 5. 技术架构与实现约束
### 5.1 前端
- Next.js 15（App Router）+ TypeScript + TailwindCSS + Shadcn UI
- 图表：Recharts 或 ECharts
- 状态管理：TanStack Query（适合异步轮询）

### 5.2 后端
- FastAPI（Python 3.11+）
- PostgreSQL（核心业务）+ Redis（缓存/队列）
- Celery + Redis Broker（异步任务）
- MinIO 或阿里 OSS（对象存储）

### 5.3 AI 工作流（推荐）
推荐：**LangGraph + 少量低代码**

说明：
- Dify 适合快速验证，不建议作为核心生产架构
- 直接 LangChain 在复杂流程中可维护性较差
- LangGraph 适配复杂、可状态化、可重试的生产流程

落地方案：
1. 使用 LangGraph 构建主链路（拍照批改）
2. Prompt + Pydantic Output Parser 强制 JSON 输出
3. 知识点匹配采用 Embedding 检索（可配合字符串匹配 + LLM rerank）
4. 所有 AI 调用统一由 Celery 异步执行

### 5.4 知识点字典维护机制（V1.0）
- 预置 + 动态补充：教师可提新增，年级主任/教研审核入库
- 向量语义匹配：以相似度匹配标准知识点，低置信度进入人工审核
- 分阶段推进：V1.0 聚焦“数学 + 语文”

## 6. 接口规范示例（AI 批改）
### 输入
- `image`
- `question_id`（可选）
- `teacher_id`

### 输出（强制 JSON）
```json
{
  "task_id": "string",
  "status": "success/processing/failed",
  "result": {
    "question_id": "Q001",
    "is_correct": false,
    "student_answer": "28",
    "analysis": "计算过程进位错误...",
    "matched_knowledge_point": {
      "id": "KP_MATH_2_012",
      "name": "两位数乘法",
      "subject": "math"
    },
    "confidence": 0.88
  }
}
```

### 幂等性与并发控制
- 幂等键：`teacher_id + image_md5`
- 晚高峰批量请求通过 Redis + Celery 排队，前端轮询任务状态

## 7. 系统分层设计
1. 前端层（Web / 移动 H5 + PWA）
   - 工作台（Dashboard）
   - 学生档案（Profile）
   - 学情大屏（Analytics）
2. 业务逻辑层（FastAPI）
   - 文件上传预处理
   - 业务路由与 AI Agent 调度
   - 数据聚合输出图表 JSON
3. AI 核心层（Agents）
   - 视觉识别（Vision OCR）
   - 批改诊断 Agent
   - 行为分析 Agent
4. 数据层
   - 关系库：学生/教师/知识点/成绩
   - 对象存储：照片与作业图像
   - 向量库（可选）：错题相似检索与知识点语义匹配
